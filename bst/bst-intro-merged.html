Binary Trees and
Binary Search Trees (BSTs)

A foundational hierarchical data structure enabling efficient searching, sorting, and dynamic data management.

What is a Binary Tree?

A Binary Tree is a hierarchical data structure in which each node has at most two children, referred to as the left child and the right child. Binary trees are a fundamental concept in computer science and serve as the structural foundation for many specialized variants, including Binary Search Trees (BSTs), AVL Trees, and Heaps.

Types of Binary Trees

Full Binary Tree

Every node has either exactly 0 or 2 children. No node has only one child.

Complete Binary Tree

All levels are completely filled except possibly the last, which is filled sequentially from left to right. (Crucial for Heaps!)

Perfect Binary Tree

All internal nodes have exactly two children, and all leaf nodes are at the same depth level.

Binary Search Tree (BST)

A binary tree enforcing a specific ordering property for efficient lookups (discussed below).

Common Applications

  • Expression Trees: Representing arithmetic expressions where leaves are operands and internal nodes are operators.
  • Decision Trees: Used in machine learning for classification and regression tasks.
  • Heaps: A specialized complete binary tree used in priority queues and heap sort — we will revisit and implement a min-heap later in the course!
  • Binary Search Trees (BSTs): Used for efficient searching, insertion, and deletion operations.

What is a Binary Search Tree?

A Binary Search Tree (BST) is a specialized binary tree in which nodes are organized according to the following ordering property:

  • All values in the left subtree of a node are less than that node's value.
  • All values in the right subtree of a node are greater than that node's value.
  • This property applies recursively to every node in the tree, not just to immediate children.

Note: Standard BSTs do not allow duplicate values. Each key must be unique in the tree.

Why Do We Need BSTs?

BSTs are particularly useful when you need to maintain a dynamically changing dataset and perform frequent searches. Real-world applications include database indexing, file systems, and autocomplete features in search engines.

Time Complexity of Common Operations

Operation Average Case (Balanced) Worst Case (Unbalanced)
Search O(log n) O(n)
Insertion O(log n) O(n)
Deletion O(log n) O(n)
⚠ The Worst-Case Scenario: O(n) occurs when values are inserted in sorted order (e.g., 1, 2, 3, 4, 5), causing the BST to degenerate into a structure that resembles a linked list with no branching. We will solve this problem later in the course with self-balancing trees!

Tree Traversals

Tree traversal is the process of visiting every node in a tree exactly once, in a defined order. The three depth-first traversals differ in when the current node is visited relative to its subtrees. The following BST is used throughout this section: 

      8
     / \
    3   10
   / \    \
  1   6    14
     / \   /
    4   7 13
Depth-First Traversals

1. Pre-order

Node → Left → Right

Visit the current node before traversing its subtrees.
Use cases: Creating a copy of the tree; prefix expression notation.

8, 3, 1, 6, 4, 7, 10, 14, 13
Most Common

2. In-order

Left → Node → Right

Visit the current node between its subtrees.
Use cases: Produces nodes in sorted ascending order for a BST.

1, 3, 4, 6, 7, 8, 10, 13, 14

3. Post-order

Left → Right → Node

Visit the current node after both subtrees.
Use cases: Deleting a tree (children freed before parent); evaluating expression trees.

1, 4, 7, 6, 3, 13, 14, 10, 8
Breadth-First Traversal

4. Level-order (BFS)

Process all nodes at the current depth level before advancing to the next, visiting left to right within each level. Unlike the depth-first traversals above, this requires a queue rather than recursion.

Use cases: Serializing/deserializing a tree; finding the shortest path in an unweighted tree; printing a tree level by level.

Level 0 → Level 1 → Level 2 → …
8, 3, 10, 1, 6, 14, 4, 7, 13

Implemented using a queue (std::queue in C++).

Recursive Nature of Tree Operations

Because trees are inherently recursive structures — every subtree is itself a valid BST — most operations on BSTs are most elegantly expressed using recursion.

Insertion

  1. Start at the root.
  2. Recursively move left (if smaller) or right (if larger) based on a comparison with the current node's value.
  3. Insert the new node at the first empty (null) position encountered.

Search

  1. Compare the target value to the current node.
  2. If equal, the search is complete.
  3. If the target is less, recurse into the left subtree; if greater, recurse into the right subtree.

Deletion

  1. Leaf node — simply remove it.
  2. One child — replace the node with its single child.
  3. Two children — replace the node's value with its in-order successor (the leftmost node in its right subtree), then delete that successor.
