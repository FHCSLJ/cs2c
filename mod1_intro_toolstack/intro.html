Module 1 Overview:
Introduction & Setup

Revisiting our C++ toolstack, remote development environment, and course project workflow.

This Week

This week, we’ll dust off our C++ brains, get our development environments set up, and complete a warmup project in two parts to familiarize ourselves with our course project workflow and requirements.

If you are continuing on from my previous C++ courses, much of the workflow will be review (VSCode, git, GitHub, Codespaces, debugging, testing), but we will also be introducing some new elements, namely CMake and a little splash of what we might call continuous integration. Let’s go!

Reference Links

Together, these tools form the technology stack for our course development environment. You don’t need to install any of them yourself — they come pre-configured in our GitHub Codespace.

VSCode

Our code editor, running inside the course Codespace.

GitHub

Where our repositories live. All project submissions go through here.

GitHub Codespaces

Our cloud development environment. A consistent, pre-configured workspace for everyone.

Git

Version control. How we track changes and submit work.

g++

The GNU C++ compiler. Turns our source code into an executable.

make

A build automation tool that manages compilation commands.

CMake

A build system generator that sits above make and manages build configurations.

Catch2

Our C++ testing framework. Used alongside CTest for automated project tests.

Valgrind

A memory analysis tool for catching leaks, invalid reads, and other memory errors.
