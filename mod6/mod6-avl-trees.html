AVL Trees

Self-balancing binary search trees that guarantee O(log n) performance by enforcing a strict height invariant after every operation.

From BST to Balanced Tree

A regular BST provides O(log n) average performance, but only when the tree stays roughly balanced. Insert values in sorted order and the BST degenerates into something much worse:

Balanced BST

    4
   / \
  2   6
 / \ / \
1  3 5  7
  • Height: 3
  • 7 nodes
  • Search: O(log 7) ≈ 3 steps

Degenerate BST

1
 \
  2
   \
    3
     \
      4
       \
        5
         \
          6
           \
            7
  • Height: 7
  • 7 nodes
  • Search: O(7) = O(n) steps
⚠ The degenerate tree is structurally a linked list. All three core BST operations fall back to O(n). The O(log n) guarantee only holds when the tree is balanced.

The AVL Invariant

AVL trees (named after their inventors Adelson-Velsky and Landis) are self-balancing BSTs that restore balance automatically after every insertion or deletion. The key constraint:

AVL Balance Property

For every node in the tree, the heights of its left and right subtrees may differ by at most 1. Any insertion or deletion that violates this property triggers a rotation to restore it.

Two quantities are central to tracking and enforcing this property:

  • Height of a node: the length of the longest path from that node down to a leaf. A null pointer has height −1; a leaf has height 0.
  • Balance factor: height(left subtree) − height(right subtree). A balanced node has a balance factor of −1, 0, or 1.

Heights and Balance Factors

Computing height recursively is straightforward but expensive if called repeatedly. The standard solution is to cache the height in each node and update it in place.

Recursive height (for reference)

int get_height(node* current)
{
    if (current == nullptr)
    {
        return -1;
    }

    return 1 + std::max(get_height(current->left), get_height(current->right));
}

Cached height in the node struct

struct avl_node
{
    int data;
    avl_node* left;
    avl_node* right;
    int height; // cached height
};

int get_height(avl_node* current)
{
    if (current == nullptr)
    {
        return -1;
    }

    return current->height;
}

void update_height(avl_node* current)
{
    if (current != nullptr)
    {
        current->height = 1 + std::max(get_height(current->left),
                                       get_height(current->right));
    }
}

int get_balance_factor(avl_node* current)
{
    if (current == nullptr)
    {
        return 0;
    }

    return get_height(current->left) - get_height(current->right);
}

Caching trades a small amount of memory per node for significantly cheaper balance checks during insertions and deletions.

Rebalancing: The Four Rotation Cases

When a balance factor falls outside [−1, 1], exactly one of four structural cases applies. Each has a single rotation (or pair of rotations) that restores balance in O(1) time.

Left-Left (LL) — single rotation with left child

Imbalance at z: balance factor > 1 and left child’s balance factor ≥ 0. Call rotate_with_left_child(z): y becomes the new root, and z drops to become y’s right child.

      z                                     y
     / \                                  /   \
    y   T4    rotate_with_left_child(z)  x     z
   / \         ─────────────────>       / \   / \
  x   T3                               T1 T2 T3 T4
 / \
T1 T2

Right-Right (RR) — single rotation with right child

Imbalance at z: balance factor < −1 and right child’s balance factor ≤ 0. Call rotate_with_right_child(z): y becomes the new root, and z drops to become y’s left child.

  z                                              y
 / \                                            / \
T1  y     rotate_with_right_child(z)           z   x
   / \    ─────────────────>                  / \ / \
  T2  x                                     T1 T2 T3 T4
     / \
    T3 T4

Left-Right (LR) — double rotation

Imbalance at z: balance factor > 1 and left child’s balance factor < 0. First call rotate_with_right_child on the left child, then call rotate_with_left_child on z.

    z                                z                            x
   / \                              / \                          / \
  y   T4   rotate_with_right_      x   T4   rotate_with_left_   y   z
 / \        child(y)              / \        child(z)          / \ / \
T1  x      ──────────>           y   T3      ──────────>     T1 T2 T3 T4
   / \                          / \
  T2 T3                        T1 T2

Right-Left (RL) — double rotation

Imbalance at z: balance factor < −1 and right child’s balance factor > 0. First call rotate_with_left_child on the right child, then call rotate_with_right_child on z.

   z                                z                              x
  / \                              / \                           /   \
T1   y    rotate_with_left_       T1  x     rotate_with_right_  z     y
    / \    child(y)                  / \     child(z)          / \   / \
   x  T4  ──────────>               T2  y    ──────────>      T1 T2 T3 T4
  / \                                  / \
 T2 T3                                T3 T4

AVL Insertion

Insertion follows standard recursive BST insertion, then unwinds the call stack updating heights and rotating wherever the balance property is violated:

avl_node* insert(avl_node* root, int key)
{
    // 1. Standard BST insertion
    if (root == nullptr)
    {
        avl_node* new_node = new avl_node;
        new_node->data   = key;
        new_node->left   = nullptr;
        new_node->right  = nullptr;
        new_node->height = 1;
        return new_node;
    }

    if (key < root->data)
        root->left = insert(root->left, key);
    else if (key > root->data)
        root->right = insert(root->right, key);
    else
        return root; // duplicate keys not allowed

    // 2. Update cached height
    update_height(root);

    // 3. Check balance factor and rotate if needed
    int balance = get_balance_factor(root);

    // Left-Left
    if (balance > 1 && key < root->left->data)
        return rotate_with_left_child(root);

    // Right-Right
    if (balance < -1 && key > root->right->data)
        return rotate_with_right_child(root);

    // Left-Right
    if (balance > 1 && key > root->left->data)
    {
        root->left = rotate_with_right_child(root->left);
        return rotate_with_left_child(root);
    }

    // Right-Left
    if (balance < -1 && key < root->right->data)
    {
        root->right = rotate_with_left_child(root->right);
        return rotate_with_right_child(root);
    }

    return root;
}

Complexity & Trade-offs

Operation Time Notes
Search O(log n) Guaranteed by the height invariant
Insertion O(log n) BST insert + O(log n) rebalancing passes
Deletion O(log n) BST delete + O(log n) rebalancing passes
Rotation O(1) Pointer rewiring only; constant work
Space (tree) O(n) One extra integer per node for cached height

Advantages

  • Guaranteed O(log n) for all three core operations — no worst-case degradation
  • Stricter balance than red-black trees means slightly faster lookups
  • Self-balancing: no manual intervention needed after insertions or deletions

Disadvantages

  • Extra memory per node for the cached height
  • More rotations per update than less strictly balanced trees (e.g. red-black)
  • Implementation complexity: four rotation cases plus careful height bookkeeping

AVL trees are an excellent fit for applications where lookups dominate and consistent performance is critical. When writes are frequent and the overhead of extra rotations matters, alternatives like red-black trees may be preferable — which is exactly why most standard library std::set and std::map implementations use red-black trees instead.
