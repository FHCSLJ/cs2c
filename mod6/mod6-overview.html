Module 6 Overview

Now that we are intimately familiar with binary search trees and the recursive algorithms with which we may apply operations to them, let us turn our attention to that worst-case O(n) running time.

What can we do about it? We will need new and different algorithms, of course!

With a binary search tree, a worst-case scenario occurs when ordered data is inserted into the tree. This degrades the BST into a linear linked list, completely defeating the purpose of the structure.

One solution is to keep the tree balanced as we insert data. That is exactly what AVL trees do. To maintain balance, however, an AVL tree must track the height of every node, which costs extra memory per node.

An alternative balancing strategy that requires no extra node space is the Splay Tree. A splay tree maintains balance in the long run (but not necessarily for any single operation) in a somewhat surprising way: as data is accessed, the tree rotates that data up to the root, reshuffling other elements in the process.

We will implement splay algorithms for our midterm programming project this week. It is a fun and challenging project!
