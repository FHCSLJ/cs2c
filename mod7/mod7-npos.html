std::string::npos

A sentinel value, a very large number, and six ways to find it.

What Is npos?

std::string::npos
A constant static member of the std::string class. We can think of it as meaning “no position.” It is used as a sentinel value to indicate that no match was found during a string search operation, and we can use it similarly in our own code to signal a failed position lookup.

Its value is the largest possible value for size_t, which on a 64-bit system is 18,446,744,073,709,551,615 (that is, 264 − 1). This works as a sentinel because size_t is guaranteed to be large enough to represent the size of any object or the number of elements in any container. Even if a container held size_t max elements, the largest valid index would be one less. The maximum value is therefore a natural stand-in for “no index” or “no position.”

Exploring the Value

We can print the value of std::string::npos directly and confirm it is just a number. The program below also shows several other ways to arrive at the same max size_t value — some straightforward, others less so and even implementation specific:

#include <iostream>
#include <cmath>
#include <limits>

int main()
{
    // Direct: print npos itself
    std::cout << std::string::npos << std::endl;

    // 2^64 - 1 via pow(): the subtraction loses precision (ULP at
    // 2^64 is 4096, so -1 rounds back to 2^64), and casting that
    // to size_t is implementation-defined -- happens to work here
    std::cout << static_cast<size_t>(std::pow(2, 64) - 1) << std::endl;

    // Left shift: conceptually correct, but shifting by an amount
    // >= the bit width of the type is undefined behavior -- works
    // in our dev env, but not portable
    std::cout << (static_cast<size_t>(1) << 64) - 1 << std::endl;

    // Split the shift to avoid overflow
    std::cout << (static_cast<size_t>(1) << 63) - 1
                 + (static_cast<size_t>(1) << 63) << std::endl;

    // Bitwise NOT of 0: flips all 0 bits to 1
    std::cout << ~static_cast<size_t>(0) << std::endl;

    // Unsigned wraparound: -1 wraps to max
    size_t max = -1;
    std::cout << max << std::endl;

    // Explicit: numeric_limits
    std::cout << std::numeric_limits<size_t>::max() << std::endl;
}

All seven approaches produce the same value. A few notes worth highlighting:

  • The pow() approach actually has two problems. First, the subtraction pow(2,64) - 1 loses precision: at the scale of 264, adjacent representable double values are 4096 apart, so subtracting 1 rounds straight back to 264. Second, casting a double value that exceeds size_t’s maximum to size_t is implementation-defined behavior. It produces max size_t on this platform, but that is not guaranteed.
  • The 64-bit left shift (1 << 64) is undefined behavior in C++: shifting by an amount equal to or greater than the bit width of the type is not defined by the standard. It happens to work in our dev environment but is not portable.
  • ~static_cast<size_t>(0) and assigning -1 to a size_t are both idiomatic C++ ways to get the max unsigned value. The latter relies on well-defined unsigned wraparound.
  • std::numeric_limits<size_t>::max() from <limits> is the most explicit and portable choice.
