Hash Tables

Module 7 Overview — O(1) average time for access, insertion, and removal.

Can We Do Better Than O(log n)?

Arrays give us constant-time access by index. Linked lists give us constant-time insertion and removal, provided we already know where to do that work, which is a significant caveat. Binary search trees represent a solid O(log n) compromise on all three operations. But can we do even better?

Enter, hash tables.

Hash Table
A data structure that implements an associative array: a structure that maps keys to values (or elements to positions). It uses a hash function that takes a key as input and computes an index into an array of buckets or slots, where the corresponding value can be found. With a good hash function and a low load factor, hash tables achieve O(1) average time complexity for access, insertion, and removal.

The key insight is that instead of searching for an element, we compute where it lives based on the element itself. That is where the magic happens.

Handling Collisions

When two different keys hash to the same index, we call that a collision. Collisions are unavoidable in practice, so every hash table implementation needs a strategy for handling them. Two major approaches exist:

Chaining

Each slot in the array holds a bucket of items that share the same hash index. The bucket can be implemented as a linked list, a binary search tree, or any other structure. Lookup requires hashing to the right bucket, then searching within it.

Open Addressing

All items are stored directly in the array slots. When a collision occurs, a probing algorithm finds the next available slot. This week's programming project has you implement two types of probing as you build a hash table from scratch.

What Makes a Good Hash Function?

The goal of a hash function is to distribute keys uniformly across the table to minimize collisions. A good hash function has three properties:

  • Deterministic — the same input always produces the same output.
  • Efficient — the function is quick to compute.
  • Uniform distribution — keys spread evenly across available slots, avoiding clustering.

We will also explore load factor (the ratio of stored items to total slots) in this week's project. Keeping the load factor low is essential to preserving O(1) average performance.
