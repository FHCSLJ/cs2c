So Many Sorts!

Welcome back. What did you come up with? This problem has been studied extensively, and there are many well-known approaches. See if yours resembles any of these:

Bubble Sort

Repeatedly swap adjacent elements that are out of order.

Insertion Sort

Build a sorted prefix one element at a time by inserting each into position.

Selection Sort

Repeatedly select the minimum from the unsorted remainder.

Shellsort

Generalize insertion sort by sorting elements far apart before closing the gap.

Mergesort

Divide in half, sort each half recursively, then merge the results.

Heapsort

Build a max-heap, then repeatedly extract the maximum.

Bucket Sort

Distribute elements into buckets, sort each bucket, then concatenate.

Radix Sort

Sort digit by digit (or character by character) from least to most significant.

Quicksort

Pick a pivot, partition around it, and sort each partition recursively.

Why Quicksort?

Quicksort has a worst-case of O(n^2), which it shares with bubble sort, insertion sort, and selection sort. But its average case is O(n log n), and in practice it tends to outperform other O(n log n) algorithms due to smaller constant factors and generally good cache behavior.

Algorithm Average Case Worst Case
Bubble / Insertion / Selection Sort O(n^2) O(n^2)
Mergesort / Heapsort O(n log n) O(n log n)
Quicksort O(n log n) O(n^2)

If you have never seen quicksort before, you will not believe how concise it is.
