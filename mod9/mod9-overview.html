Module 9 Overview

Binary Heaps and Priority Queues

This Week’s Focus

Our top priority this week is exploring the binary heap as an efficient implementation of the priority queue ADT.

A regular queue follows FIFO (first-in, first-out). A priority queue is different: each element has a priority, and the highest-priority element is removed first. The data does not need to be fully sorted at all times, but we must always be able to identify the next highest-priority element efficiently.

Key idea: Binary heaps give us the practical balance we want, simple structure plus fast operations.

Why Binary Heaps Work

We can think of a binary heap as a binary tree (not a BST) with two core invariants:

  1. Heap-order property: In a min-heap, each parent is less than or equal to its children. In a max-heap, each parent is greater than or equal to its children. This guarantees the highest-priority element at the root.
  2. Complete-tree structure: Every level is full except possibly the last, and nodes fill from left to right.

That structural regularity is why heaps are usually stored in an array, no links required.

Peek Highest Priority

Read the root element in O(1).

Insert

Add at the end, then percolate up. Worst case O(log n), often near O(1).

Remove Highest Priority

Swap root with last, remove last, then percolate down in O(log n).

Why Priority Queues Matter

Priority queues appear everywhere: task scheduling, graph algorithms, pathfinding, and game AI behavior systems. As we move forward in the course, we will revisit and leverage this structure in additional contexts.
